# Offline experiment preparation

All commands here use synthetic fixtures. `MOCK` outputs verify software flow, not research results. Licensed SemEval XML, human question/reference review, adjudicated challenge labels, a real provider and a separately approved budget are absent.

For a target-size, wholly synthetic data-preparation smoke test, run `python -m scripts.synthetic_protocol_smoke --out outputs/synthetic_protocol`. It generates 3,041/800 synthetic XML sentences and exercises the 150/600 split, 20 packs, 120 candidate questions, subset manifest and boundary audit. Its `SYNTHETIC_TEST_ONLY` counts must never be reported as SemEval statistics.

## Dry-run conditions

Run from the repository root after installing `.venv`:

```powershell
.\.venv\Scripts\python -m eval.run_method --method a --condition main --mock --out outputs/runs/demo/main-a
.\.venv\Scripts\python -m eval.run_method --method b --condition main --mock --out outputs/runs/demo/main-b
.\.venv\Scripts\python -m eval.run_method --method c --condition main --mock --out outputs/runs/demo/main-c
.\.venv\Scripts\python -m eval.run_method --method c --condition repeats --mock --out outputs/runs/demo/repeats-c
.\.venv\Scripts\python -m eval.run_method --method b --condition gold --mock --out outputs/runs/demo/gold-b
.\.venv\Scripts\python -m eval.run_method --method c --condition gold --mock --out outputs/runs/demo/gold-c
.\.venv\Scripts\python -m eval.run_method --method c --condition ablation --mock --out outputs/runs/demo/ablation-c
.\.venv\Scripts\python -m eval.run_challenge --mock --out outputs/runs/demo/challenge
```

`repeats` writes repeat indices 1 and 2. `gold` substitutes synthetic aspect labels for B/C and marks the full source sentence as **unannotated evidence**, because gold has no rationale spans. `ablation` disables C's output checks and their repair while retaining schema, tool safety and decision budgets. Challenge extracts two synthetic candidate records; it writes no human labels or scores. The 40 formal human-authored and independently annotated pairs remain pending.

To exercise shared predicted extraction in the local comparison, prepare one ignored MOCK artifact and pass its directory to both B and C:

```powershell
.\.venv\Scripts\python -m scripts.prepare_shared_extraction --mock --out outputs/runs/demo/shared-extraction
.\.venv\Scripts\python -m eval.run_method --method b --condition main --mock --shared-extraction outputs/runs/demo/shared-extraction --out outputs/runs/demo/shared-main-b
.\.venv\Scripts\python -m eval.run_method --method c --condition main --mock --shared-extraction outputs/runs/demo/shared-extraction --out outputs/runs/demo/shared-main-c
```

Preparation validates and reuses an existing artifact without new calls. Its manifest binds raw-record, extraction-output and call-ledger hashes, model/prompt/schema provenance and the measured setup request count. B/C run manifests bind the same setup-manifest hash; resume rejects a changed artifact or a run started without it. In the four-record synthetic fixture, preparation uses four physical extraction requests; B and C then use two and four query requests respectively. Count the four setup requests once when discussing the combined physical total (10). Per-method answer rows exclude setup requests and keep separate query wall time. Repeats and C ablation can reuse this artifact; Method A and gold substitution cannot. This only checks MOCK sharing; it is not a frozen real extraction or evidence of model accuracy.

The separate `scripts.score_challenge` CLI accepts one or more extraction `predictions.json` files, an independently adjudicated local `--references` JSON file and an ignored `--out` path. It reports intended-change and stable-aspect accuracy, pair accuracy, extraction failures and subgroup support. No reference file is generated by the synthetic challenge dry-run; scoring that fixture is exercised only in tests with an explicit `SYNTHETIC_TEST_ONLY` reference. Formal scores require the 40 real pairs and documented human adjudication.

QA directories contain a config and full task hash, append-only answer rows, retained failures and explicit retry via `--retry-failed`. `model_calls.jsonl` records each actual MOCK request's stage, prompt version/hash, response hash, timestamp, measured latency and token usage; it includes raw synthetic prompts/outputs for local replay inspection and therefore stays under ignored `outputs/`. Extraction calls have no question ID or method attribution. Unknown tokens and cost remain null. Reuse a directory only with identical config/tasks; older incompatible manifests are rejected. `--max-api-requests N` uses conservative per-task bounds. The telemetry wrapper is MOCK-only and is not a live billing or approval mechanism. Live calls and dev/test CLI runs are blocked until a provider adapter and approvals exist.

## Candidates and blind review

After legally obtaining and locally parsing SemEval XML, `scripts.prepare_semeval` and `scripts.build_questions` produce ignored candidate files and separate gold references. Then run:

```powershell
.\.venv\Scripts\python -m scripts.build_subsets --questions data/processed/candidate_questions.json --out data/processed/candidate_subsets.json
.\.venv\Scripts\python -m scripts.audit_questions --questions data/processed/candidate_questions.json --references data/gold/candidate_references.json --out data/processed/candidate_question_audit.json
```

The subset script requires 20 complete six-type packs and preselects 20 repeat, 30 gold/ablation diagnostic and 30 evidence review question IDs across all packs. It uses no model outputs or gold answers. The question audit checks pack scope/overlap, empty and nonempty selections, undefined rates, tied first ranks and all three absent-metadata variants. It writes a report and exits 2 if any coverage gap remains; a gap-free result still says `CANDIDATE_REVIEW_REQUIRED`, never frozen or human-approved. The real 120-question audit awaits licensed sampled records. The synthetic challenge pair is likewise only a dry-run candidate. Follow [annotation guide](annotation_guide.md).

After reviewed main A/B/C runs exist, generate method-blinded packets:

```powershell
.\.venv\Scripts\python -m scripts.make_blind_review --runs outputs/runs/main-a outputs/runs/main-b outputs/runs/main-c --subsets data/processed/candidate_subsets.json --out outputs/blind_review
```

`review_items.csv` omits method; `private_mapping.csv` stores the key separately. Inspect answer prose for self-identifying method text before handing packets to reviewers. Both files may contain licensed review content and stay in ignored local output. The exporter writes no human judgments and refuses to overwrite a mapping. The annotation guide provides blank judgment headers for independent reviewers and adjudication.

## Scoring and report data

```powershell
.\.venv\Scripts\python -m scripts.summarize_runs --runs outputs/runs/demo/main-a outputs/runs/demo/main-b outputs/runs/demo/main-c outputs/runs/demo/repeats-c outputs/runs/demo/gold-b outputs/runs/demo/gold-c outputs/runs/demo/ablation-c --references data/demo/core_reference.json --out outputs/runs/demo/report.json
```

The independent scorer stamps `MOCK_ONLY_NOT_RESEARCH_RESULT`, separates conditions, reports missing/failed final rows and unknown costs, pairs question IDs and success differences, and summarizes repeat disagreement. Scoring uses each task's latest attempt. `attempt_rows`, `failed_or_partial_attempt_rows`, `api_requests_known`, `api_requests_unknown_rows` and `cost_usd` cover every retained attempt, including failed attempts followed by explicit retries; unknown cost remains null. Challenge has no score before human labels exist. Use the [blank report template](report_template.md) for reviewed real results only.

For B/C main runs made with `--shared-extraction`, pass that same artifact directory as `--shared-extraction` to `scripts.summarize_runs`. The optional `shared_extraction` section verifies both run manifests' source/setup hash, split, question list, prompt and model binding. It reports setup calls once, observed B/C query calls, each answer ledger's known/unknown requests and reconciliation status, and a combined physical request count only when both call logs exist. Setup and method costs are separate and combined cost remains null whenever any component is unknown. Other conditions and Method A are outside this combined B/C count. The ordinary report without this option remains available for older independent MOCK dry-runs.

```powershell
.\.venv\Scripts\python -m scripts.summarize_runs --runs outputs/runs/demo/shared-main-b outputs/runs/demo/shared-main-c --references data/demo/core_reference.json --shared-extraction outputs/runs/demo/shared-extraction --out outputs/runs/demo/shared-report.json
```

When local `model_calls.jsonl` exists, each run summary also contains `model_call_efficiency`. It validates MOCK mode, config/task identity and consecutive call indices; counts extraction and query calls by stage, failed calls, known/unknown input and output tokens, and known/unknown cost. It reports measured per-call median and nearest-rank P95 latency, plus the sum of non-extraction model-call latencies for each query attempt. This last quantity excludes Python analysis tools and other wall time, so it is not the full warm-query latency promised for a real experiment. `physical_minus_answer_requests` highlights unmatched call rows only when answer-row usage is complete; a crash may leave a call without an answer row. Missing telemetry is marked unavailable, not zero. Raw synthetic prompts/responses are not copied into the report.

The MOCK host also measures `query_wall_latency_ms` from the point the extraction artifact is ready until the method returns, including parser, analysis tools, verification and answer generation. When this run performs extraction, it separately records `extraction_wall_latency_ms`; Method A and gold substitution do not report an extraction duration. The independent report summarizes all retained attempts as `warm_query_wall_latency_ms` (median/nearest-rank P95), counts missing query timings, and keeps full runner `attempt_wall_latency_ms` and reported `extraction_wall_latency_ms` separate. A failed attempt with no host timing remains missing rather than receiving a zero. These are local MOCK wall times and cannot establish real-provider performance.

## Budget and real-run approval

The plan has 360 main + 120 repeat + 60 gold + 30 ablation = **570 method-level answers**. Conservative arithmetic is 2,270 query requests, up to 1,200 shared main extraction requests (600 records × 2 attempts), and up to 160 challenge extraction requests (80 records × 2 attempts), totaling **3,630** before pilot, conditioned sentiment or optional work. This assumes no cache savings and is not measured usage. `scripts.estimate_budget` requires an actual provider/model, price source/date, per-request token upper bounds and prices; its fixture test price is not a quote.

Before a real pilot or formal run, verify licensed files and source hashes; duplicate audit; frozen question/reference/subset hashes and human sign-off; human challenge labels; exact provider/model/version/parameters and prompts; concurrency, timeout and retry policy; token bounds, current price source/date/currency, request and fee caps; data transfer/privacy rules; and explicit approval for the dev pilot or formal holdout. Add pilot and conditioned sentiment costs to the estimate. The current code intentionally blocks live execution.
